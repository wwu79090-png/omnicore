# Contributing

## Local Setup

```bash
npm install
npm test
npm run lint
npm run build:prod
npm link
```

For a no-friction desktop start, double-click `OmniCore_Dev_Launcher.bat` on Windows or `OmniCore_Dev_Launcher.command` on macOS.

## Contributor Sandbox Preview

Use `npm link` for fast local addon/app checks:

```bash
npm ci
npm link
cd ../your-omnicore-game
npm link omnicore
npm test
```

Use `Dockerfile.contributor` when you need a clean preview that mirrors CI without touching your local Node installation:

```bash
docker build -f Dockerfile.contributor -t omnicore-contributor .
docker run --rm omnicore-contributor
```

The image installs dependencies, runs `npm run quality:gate`, and keeps the generated environment disposable. Pull requests also run the Contributor Preview workflow, which produces a runnable `dist` package plus reports for contract tests, backend/network checks, low-memory benchmark, and production readiness.

## Development Rules

- Keep `src/lean/core/` limited to `Bootstrap`, `EventBus`, and `Store`.
- Place optional capabilities in `src/lean/addons/`.
- Prefer dependency-free native APIs for launcher, generators, and platform glue.
- Add tests before changing behavior.
- Preserve existing `OmniCore.Game` compatibility.

## Addon Contributions

Each Addon should expose:

```js
export default class MyAddon {
  mount(bootstrap, options) {}
  unmount(bootstrap) {}
}
```

Addon README files should include purpose, public API, minimal example, and teardown behavior.

## Pull Request Checklist

- Unit tests pass with `npm test`.
- Core API contract tests pass with `npm run test:contract`.
- Lint passes with `npm run lint`.
- Production build passes with `npm run build:prod`.
- Performance gate passes with `npm run benchmark:ci`.
- New APIs are documented in `README.md` or `docs/api/`.
- Generated files are reproducible from scripts.
- Breaking changes are explicitly marked with `BREAKING CHANGE:` in the commit body and the PR description.
- Breaking changes must trigger a major version bump through `standard-version`; do not manually edit `package.json` versions or `CHANGELOG.md`.
- Public API changes include contract-test updates under `tests/contract/`.

## Versioning

OmniCore uses Conventional Commits and `standard-version`:

- `fix:` creates a patch release.
- `feat:` creates a minor release.
- `BREAKING CHANGE:` creates a major release.
- Version numbers and `CHANGELOG.md` are generated by `npm run release`; manual edits are not accepted.

## Review Requirements

Every PR must have at least one maintainer review. Reviewers should check:

- The change is scoped and does not bypass Store/EventBus data flow.
- Backward compatibility is preserved or the PR is marked as breaking.
- Tests cover the public behavior, not private implementation details.
- Debug-only tooling is gated by `debug: true`.
